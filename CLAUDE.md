# OneView marketing website — rules for Claude Code

The full project handoff (decisions, deployment state, next steps) lives in the app repo: `bongimsk80-sys/onebank-sa` → `docs/HANDOFF.md`. Read it before changing this site.

## How this site works

- Pages are generated by `tools/build.py`. Edit content there, run `python3 tools/build.py`, and commit the generated HTML. Never hand-edit the generated `*.html` files.
- Shared styles: `assets/site.css`; script (nav toggle and demo form): `assets/site.js`.
- The demo form posts to the app's `POST /api/enquiries` (`APP_URL` in `tools/build.py`). The app must be live with that endpoint before this site's rebuild is merged.
- `netlify.toml` sets a strict Content Security Policy: no inline styles or scripts. If `APP_URL` changes, update `connect-src` too.
- Pushing to `main` deploys to Netlify through `.github/workflows/deploy.yml`. Work on a branch and open a pull request.

## Content rules

- The product is **OneView**. Never use "bank" in the product or company name (Banks Act s22(5)).
- Label every feature Live in beta, In integration, In development or Planned. Nothing is "live" unless customers can use it.
- Payments are simulated during the beta. Never show simulated payments as GMV, volume, uptime or traction.
- Bank data via Stitch is "in integration" until the owner confirms the Stitch contract. Do not mention Yodlee as available.
- Testimonials only from named people who consented in writing. No competitor claims without a source.
- Founder credentials must match the owner's certificates exactly; confirm with the owner before changing them.

## Before a pull request

Run `python3 tools/build.py`, preview with `python3 -m http.server 8080`, and check the home, product, pricing and demo pages at desktop and phone widths.
